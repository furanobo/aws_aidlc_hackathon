- **発表時間**: 15分プレゼン + 5分質疑応答
- **勝利条件**: 決勝進出 → AWS Summit Japan 2026 で発表

| 審査基準 | 審査員が見るポイント | 我々の戦い方 |

## コンセプトのとがらせ方

### 原則: 「笑えるけど本質を突いている」

1. **極端化** — 「人をダメにする」を究極まで突き詰める。中途半端はNG
2. **哲学的正当化** — Larry Wallの「怠慢は美徳」を引用し、ダメになることの正しさを論証
3. **共感の罠** — 審査員自身が「これ欲しい」と思わせたら勝ち
4. **社会的意義の逆説** — 人をダメにすることで実は生産性が上がる/幸福度が上がるパラドックス

### 差別化ポイント

- 他チームは「便利ツール」に留まりがち → 我々は**「堕落のエコシステム」**を提示
- 単なるアプリではなく**行動変容（悪い方向への）の仕組み**として設計
- テーマの解釈の深さで知性を見せる

## 場の掌握方法

### 開始15秒ルール

- **冒頭で審査員の心を掴む一言/行動**を用意
- 選択肢: 挑発的な問いかけ / 衝撃のデモ / 笑いを取る自虐
- 例:「皆さん、今日から人生の生産性を下げるお手伝いをさせてください」

### プレゼン中の支配術

- **視線**: 審査員全員と順にアイコンタクト
- **間(ま)**: 重要なスライドの前に2秒の沈黙
- **声のトーン**: デモ時は興奮気味に、哲学パートは落ち着いて
- **動き**: ステージ全体を使う。定位置に固まらない

### ノンバーバルコミュニケーション

| 場面 | 体の使い方 |
|-----|----------|
| 冒頭 | 胸を張り、両手を広げて歓迎のジェスチャー |
| デモ中 | 画面を指差し、体は聴衆に向ける |
| 数字/成果 | 指でカウント、手で大きさを示す |
| 結論 | 正面を向き、手を合わせてクロージング |

### バーバルコミュニケーション

- **パワーワード**: 「革命」「堕落」「美徳」「究極」を意図的に配置
- **反復**: キーフレーズを3回繰り返す（頭・中盤・締め）
- **問いかけ**: 審査員に考えさせる質問を挟む（答えは求めない）
- **ストーリー**: 個人の体験から始めて普遍に広げる

## 他チームとの差別化（蹴落とし戦略）

### 予測される他チームの弱点

1. **デモが動かない** → 我々は安定した環境で確実に動かす
2. **テーマの解釈が浅い** → 我々は哲学まで掘り下げる
3. **AI-DLCを「やりました」報告** → 我々は「使いこなして学んだ」ストーリー
4. **プレゼンが退屈** → 我々は笑い・感動・知性の三段構え

### ポジショニング

- 「真面目にふざける」ポジションを取る
- 技術力は見せつつ、エンタメ性で圧倒する
- 審査員の記憶に残る**印象的なワンフレーズ**を残す

---

## 審査員（AI-DLC提唱者）の心理分析

### 彼らが見たいもの

1. **AI-DLCが実際に機能する証拠** — 方法論が正しいことの実証
2. **チームがAIと協働できている証拠** — 人間は監督者として機能しているか
3. **創造性がAI-DLCで増幅される証拠** — プロセスがアイデアを殺さないこと
4. **楽しんでいる証拠** — ハッカソンの本質は学びと楽しさ

### 我々の見せ方

- AI-DLCを「制約」ではなく「ブースター」として語る
- 「このプロセスのおかげでこのアイデアが生まれた」具体エピソードを入れる
- Inceptionフェーズでのチーム議論の活性化を強調
- AIの出力をそのまま使わず、チームで判断・改善した事例を見せる

## プロダクトとテーマの整合性

### 「人をダメにする」の定義を明確に

- 単なる「楽をする」ではない
- **能動的に怠惰を助長する仕組み**であること
- ユーザーが自覚的にダメになっていく/無自覚にダメになっていく、どちらかのアプローチを明確に

### 整合性チェックリスト

- [ ] サービス名がテーマを体現しているか
- [ ] 1文で「なぜこれが人をダメにするか」説明できるか
- [ ] 使えば使うほどダメになる仕組みがあるか
- [ ] 「ダメにする」の度合いが笑えるレベルか
- [ ] Larry Wallの「怠慢」との接続が自然か
