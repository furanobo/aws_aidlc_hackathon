# 予選突破チーム vs 敗退チームの決定的差異分析

> **注**: このドキュメントはAI-DLCハッカソンの審査基準・構造分析と、
> ハッカソンプレゼン一般のベストプラクティスから構成。
> 実際のプレイリスト動画を視聴した際に、具体チーム名と事例を下部の表に追記してください。

---

## 決定的差異サマリー: 5つの分水嶺

| # | 分水嶺 | 決勝進出チーム | 予選敗退チーム |
|---|--------|-------------|-------------|
| 1 | **デモの「動き」** | 実際にリアルタイムで操作。ユーザー体験の流れが見える | スライドで説明。スクショ。「動く予定です」 |
| 2 | **テーマの「深さ」** | テーマを再解釈し、独自の哲学を持っている | テーマに触れるが表面的。「便利ツール」で終わる |
| 3 | **AI-DLCの「語り方」** | プロセスから得た洞察・判断を語る | プロセスの手順を説明する（やりました報告） |
| 4 | **15秒の「掴み」** | 冒頭で審査員の感情を動かす | 自己紹介から始まり、淡々とスライドを進める |
| 5 | **ストーリーの「一貫性」** | 1本の太い物語が最初から最後まで通る | 機能説明の羅列。何を解決するか不明瞭 |

---

## 差異1: デモの「動き」

### 決勝進出パターン

```
✅ ライブデモがある（たとえ小さくても）
✅ ユーザーシナリオに沿って操作する（物語がある）
✅ デモ中にリアクションや笑いが起こる
✅ 画面遷移がスムーズ（事前にデータを仕込んである）
✅ 失敗した場合のバックアップ動画がある
```

### 予選敗退パターン

```
❌ スクリーンショットやモックアップの紹介
❌ 「ここをクリックすると〜になります」という口頭説明
❌ デモが途中でフリーズ/エラーしてパニック
❌ ターミナルのログを見せて「動いています」
❌ デモの前提説明が長すぎて操作時間が短い
```

### 我々への教訓

- デモは**最悪でも3分**確保する。2分では短すぎる
- デモ前にデータを完璧に仕込む。初期状態から見せるのではなく「ある程度育ったぶた」を見せる
- デモシナリオは**台本を書く**。即興でやると迷う
- バックアップ動画を録画しておく（画面収録、30秒でも良い）

## 差異2: テーマの「深さ」

### 決勝進出パターン

```
✅ テーマの独自解釈を冒頭で宣言する
✅ 「なぜこれが人をダメにするか」のメカニズムを説明できる
✅ 行動心理学・行動経済学・UX理論との接続がある
✅ 審査員が「その視点はなかった」と思う切り口
✅ ユーモアと知性のバランス（真面目にふざける）
```

### 予選敗退パターン

```
❌ テーマへの言及が「人をダメにします」の一言で終わる
❌ 便利ツールを作って「これで楽になる→ダメになる」という浅い接続
❌ テーマと機能の関係が後付け感がある
❌ 「人をダメにする」要素が機能の1つに過ぎない（全体設計に染みていない）
❌ テーマの解釈に独自性がなく、誰でも思いつくレベル
```

### 我々への教訓

- テーマ解釈は**プレゼンの最初の2分で明示的に語る**
- 「ぶたそだて」の場合: 「罪悪感をドーパミンに変換する装置」という定義を冒頭で打つ
- 「なぜダメになるか」を3段論法で説明する時間を確保
- 審査員に「そう来たか」と思わせる知的驚きが差別化の鍵

## 差異3: AI-DLCの「語り方」

### 決勝進出パターン

```
✅ 「AI-DLCのおかげで○○に気づいた」（具体的洞察）
✅ 「AIはこう提案したが、我々はこう判断した」（人間の監督ロール）
✅ プロセスの中で起きた「予想外の発見」のエピソード
✅ Before/After — AI-DLCなしとの比較
✅ AI-DLCを「ブースター」として語る（制約ではなく加速装置）
```

### 予選敗退パターン

```
❌ AI-DLCの各フェーズを順番に説明する（教科書の朗読）
❌ 「Inceptionフェーズをやりました。次にConstructionをやりました。」
❌ 成果物のファイル一覧を見せる
❌ AI-DLCの説明に時間を使いすぎて他が薄い
❌ プロセスに従ったことを「苦労」として語る
```

### 我々への教訓

- AI-DLCパートは**最大3分**。短く鋭く
- 語ることは**2つのエピソード**に絞る（多すぎると印象が散る）
- 「AI-DLCの説明」は一切しない（審査員は知っている）
- 「使って何が起きたか」だけを語る

## 差異4: 15秒の「掴み」

### 決勝進出パターン

```
✅ 冒頭で強い問いかけ/宣言/行動がある
✅ 審査員が笑う or 身を乗り出す瞬間が最初にある
✅ プロダクト名が印象的に提示される
✅ 「この15分で何が得られるか」が冒頭で予告される
✅ チーム全体のエネルギーが高い
```

### 予選敗退パターン

```
❌ 「チーム○○の○○です。今日は○○について発表します。」（テンプレ開始）
❌ 自己紹介が全員分あり、1分以上かかる
❌ 最初のスライドがタイトルだけ（情報量ゼロ）
❌ 声が小さい/緊張で噛む（最初の印象が弱い）
❌ 何のプロダクトかが2分経っても分からない
```

### 我々への教訓

- **最初の一言を100回練習する**。ここだけは完璧に
- 自己紹介は最大15秒。名前とプロダクト名だけ
- 冒頭のインパクト候補:
  - 「今日、皆さんの生産性を破壊しに来ました」
  - 実際にダメな行動を記録して見せる（ライブ）
  - 審査員に問いかける「昨日、夜更かしした方？」

## 差異5: ストーリーの「一貫性」

### 決勝進出パターン

```
✅ 「課題→着想→解決→デモ→学び」の一本道が明確
✅ 各スライドが前のスライドの「だから」で繋がる
✅ 聞き終わったあとに「つまりこういうことね」と要約できる
✅ 機能は「物語の中の要素」として紹介される
✅ 冒頭の問いが、最後に回収される
```

### 予選敗退パターン

```
❌ 機能リストを順に説明する（カタログ型プレゼン）
❌ 話の流れが途切れる（唐突にAI-DLCの話が始まる等）
❌ 情報が多すぎて何が重要か分からない
❌ 結論が曖昧/尻すぼみで終わる
❌ 「あとは質問で聞いてください」で逃げる
```

### 我々への教訓

- プレゼン全体を**1文で要約**してから構成を組む
  - 例:「不健康行動を育成ゲームに変換し、人を構造的にダメにするアプリを作った」
- 各パートの冒頭に**接続詞を意識**する（「だから」「しかし」「つまり」）
- 最後に冒頭を回収する（円環構造）

## 追加観察: 勝者に共通する「空気」

### エネルギーと自信

| 決勝進出 | 予選敗退 |
|---------|---------|
| 楽しそうに話す | 緊張して早口/棒読み |
| 自分のプロダクトに誇りがある | 「まだ未完成ですが...」と予防線を張る |
| チームメンバー全員が前を向いている | 1人だけが話し、他は黙って立っている |
| 質疑で笑顔で答える | 質疑で「考えてませんでした」と返す |

### 時間管理

| 決勝進出 | 予選敗退 |
|---------|---------|
| 15分±30秒で完了 | 時間オーバーで強制終了 / 10分で終わる |
| デモに十分な時間を割く | 説明が長くデモが駆け足 |
| 各パートの配分が計算されている | 後半が時間切れで飛ばされる |

### チームワークの見せ方

| 決勝進出 | 予選敗退 |
|---------|---------|
| 発表者交代に意味がある（専門性ごと） | 「次は○○さんお願いします」（ぶつ切り） |
| 発表してない人もデモを操作する等で参加 | 発表してない人が手持ち無沙汰 |
| 質疑を適切な人に振る | 全部リーダーが答える |

## 審査員の「無意識の加点/減点」パターン

### 無意識に加点されるもの

- プロダクト名が面白い/覚えやすい
- デモ中に予想外の機能が出てくる（サプライズ感）
- テーマへの愛が伝わる（本気でダメになろうとしている）
- 技術的に「おっ」と思わせるポイントが1つある
- 質疑で即座に的確な回答ができる

### 無意識に減点されるもの

- スライドの文字が多すぎて読めない
- 専門用語の説明なしに使う（審査員は技術者だが全知ではない）
- 「時間がなくて」「まだ実装中で」という言い訳
- デモが動かないときの対応がまずい
- 質疑で「いい質問ですね」と言ってから答えない

## 我々の最終チェックリスト（この分析に基づく）

### MUST（これがないと敗退する）

- [ ] ライブデモが3分以上動く
- [ ] テーマ解釈を明示的に語るパートがある
- [ ] AI-DLCの具体エピソードが2つある
- [ ] 冒頭15秒で審査員の注意を掴む仕掛けがある
- [ ] 15分以内に収まるリハーサルを3回以上した

### SHOULD（これがあると決勝に行ける）

- [ ] デモ中に笑いが起こる仕掛けがある
- [ ] テーマの哲学的深さが伝わる（行動心理学等の接続）
- [ ] AI-DLCを「使いこなした」感が出るBefore/After
- [ ] チーム全員が何かしらの役割で登場する
- [ ] 質疑で「そこまで考えてたか」と思わせる回答がある

### NICE（これがあると圧勝する）

- [ ] 冒頭のキラーフレーズが会場の記憶に残る
- [ ] デモの中にストーリー（キャラクターの旅路）がある
- [ ] AI-DLCで「予想外の発見」があったエピソード
- [ ] 最後の一言が余韻を残す
- [ ] 審査員が「自分も使いたい」と思う瞬間がある
