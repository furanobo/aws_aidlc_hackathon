# 想定質問と回答集（5分質疑応答対策）

## 回答の原則

- **30秒以内**で答える（長いと追加質問のチャンスを失う）
- **結論 → 理由 → 具体例**の順で話す
- わからないことは正直に「検討中です」と言い、仮説を添える
- 質問の意図を読み取り、審査基準との接点を意識して回答

## カテゴリ1: MVPデモ・技術面

### Q1: このサービスの技術スタックを教えてください

**回答**: フロントエンドはFlutter（クロスプラットフォーム）、バックエンドはAWS Lambda + API Gateway + DynamoDB、インフラはCDKで管理しています。全てサーバーレスで、スケーラビリティとコスト効率を両立しています。

### Q2: なぜその技術を選んだのですか？

**回答**: AI-DLCのNFR Requirementsフェーズで、「ハッカソン期間内にMVPを出す」ことを最優先制約としました。Flutter＋サーバーレスAWSは、少人数で素早くマルチプラットフォーム対応できる組み合わせとして選定しています。

### Q3: スケーラビリティはどう担保していますか？

**回答**: サーバーレスアーキテクチャなので基本的にはAWSが自動スケールします。DynamoDBのパーティション設計とLambdaの同時実行数は、NFR Designフェーズで検討済みです。

### Q4: セキュリティ面は？

**回答**: Amazon Cognitoで認証、API GatewayでAuthorizerを挟んでいます。ユーザーデータは暗号化保存で、IAMポリシーは最小権限原則に従っています。

### Q5: デモで見せた以外の機能は？

**回答**: MVPとしてコア体験に絞っています。（具体的に1〜2個の「次に実装したい」機能を述べる）ユーザーストーリーとしては定義済みで、優先順位づけもAI-DLCプロセスの中で行っています。

## 危険な質問への対処

### 「これ本当にダメになりますか？」（テーマ適合性への疑問）

**対処**: 具体的なユーザーシナリオで「こう使うとこうダメになる」を即座に説明。データがあればなお良い。

### 「AIに作ってもらっただけでは？」（自主性への疑問）

**対処**: チームの判断ポイントを具体的に挙げる。「AIはこう提案したが、我々はこう判断した」事例。

### 「MVPにしては機能が少なくないですか？」

**対処**: 「コア体験に集中した意図的な判断」と説明。ユーザーストーリーのバックログはあるが、MVPとして価値検証に必要十分な範囲に絞ったと述べる。

## 質疑応答のテクニック

1. **質問を繰り返す** — 考える時間を稼ぎつつ、意図を確認
2. **チームメンバーに振る** — 専門性に応じて最適な人が答える
3. **「いい質問ですね」は使わない** — 陳腐。代わりにすぐ回答に入る
4. **最後の一言** — 質疑終了時に「ぜひダメになってください」等で締める
